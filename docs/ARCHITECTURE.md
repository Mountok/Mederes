# Архитектура Al-Qalam AI

Обновлено: 31 октября 2026 года.

## Компоненты

```text
Браузер
  └── React/Vite, :5173
        ├── /api/*    ───────────────► Go/Gin, :8000 ─► PostgreSQL
        ├── /ai-api/* ───────────────► Python dev AI, 127.0.0.1:8001
        ├── /ai-stream ── WebSocket ─► Python dev AI, 127.0.0.1:8002
        ├── Quran API ───────────────► текст, переводы, аудио аятов
        └── LiveKit client ──────────► LiveKit
```

Vite проксирует `/api` к Go backend, а `/ai-api` — к локальному Python-сервису. Это схема разработки. Статическая production-сборка Vite сама по себе proxy не предоставляет. Go API по умолчанию слушает loopback `127.0.0.1`; в production Nginx направляет в него внутренние запросы.

## Frontend: `app/`

Стек: React 19, React Router 7, Vite 8, Axios, LiveKit client.

Основные публичные маршруты:

- `/` — главная страница;
- `/login` — вход;
- `/ai-test` — локальная демонстрация анализа чтения;
- `/live/join`, `/live/:id` — сейчас показывают состояние недоступности.

Маршруты после авторизации:

- `/groups`;
- `/group/:id`;
- `/group/:id/journal`;
- `/lesson/:id`;
- `/quran`;
- `/staff`;
- `/live` — сейчас недоступен в UI.

Аудиозахват находится в `app/src/audio/`. `useLiveRecitation.js` передаёт mono PCM16 через WebSocket. Сервер держит запись в памяти и распознаёт перекрывающиеся окна до 12 секунд: Tarteel tiny с beam 1 для предварительной подсветки, Tarteel base с beam 5 для фонового уточнения и финального результата. Если tiny не установлена, предварительный проход использует base. Загрузка готового файла остаётся HTTP-запросом.

## Go backend: `back/`

Стек: Go 1.25, Gin, sqlx, PostgreSQL, JWT, LiveKit SDK, WebSocket.

Слои:

```text
routes → middleware → handlers → services → repositories → PostgreSQL
```

Backend отвечает за аутентификацию, роли, `school_id`, учебные сущности и LiveKit. Миграции применяются при старте. Основные роли: `teacher`, `staff`, `parent`, `student`.

AI-сущностей в миграциях пока нет. В БД отсутствуют задания на чтение, попытки, аудиообъекты, версии модели, предполагаемые ошибки и учительские проверки.

## Python AI: `ai-service/`

Рабочая цепочка локальной демонстрации:

```text
аудиофайл
  → PyAV decode
  → mono float32 16 kHz
  → проверка 1–60 сек., тишины и конечных значений
  → локально Tarteel Whisper base в CTranslate2/int8, иначе faster-whisper small; Arabic, CPU, beam=5
  → сырая расшифровка и временные сегменты
  → нормализация арабского текста
  → серверное получение выбранного диапазона из Quran API
  → динамическое выравнивание с выбранными аятами
  → состояния matched / review / tentative / pending
```

`recognition.py` не получает ожидаемый текст и возвращает сырую расшифровку. `quran_catalog.py` проверяет выбор от 1 до 114 и загружает канонический текст с кэшированием. `analysis.py` выполняет полное сравнение, `tracking.py` — сопоставление с прочитанным префиксом для живой подсветки.

`server.py` предназначен для разработки:

- слушает только `127.0.0.1` на портах 8001 (HTTP) и 8002 (WebSocket);
- для HTTP требует заголовок `X-Al-Qalam-Test: 1`, а WebSocket проверяет Origin;
- отклоняет внешние Origin;
- принимает файл до 20 МБ;
- загрузку файла хранит только временно, поток микрофона — в памяти до закрытия соединения;
- не имеет пользовательской авторизации и постоянного хранилища.

## Quran API

Frontend пробует два совместимых адреса:

1. `https://alquran.api.alislam.ru/v1`;
2. `https://api.alquran.cloud/v1`.

Через API загружаются список сур, Uthmani-текст, русские переводы и аудио. Для `/ai-test` текст и аудио выбранной суры запрашиваются динамически; аудио используется в редакции `ar.alafasy`. AI-сервис независимо получает выбранный канонический диапазон и не доверяет тексту из браузера.

Внешний API используется для показа и прослушивания. Он не заменяет датасет проверки ASR и не участвует в определении фактически произнесённых учеником слов.

## Целевая production-архитектура

```text
React
  │ HTTPS/JWT
  ▼
Go API
  ├── PostgreSQL: задания, попытки, ошибки, проверки, метрики
  ├── S3/MinIO: аудио с ограниченным сроком хранения
  └── очередь задач
        ▼
Python AI worker/API
  ├── нормализация аудио
  ├── версионированный ASR
  ├── выравнивание с выбранной сурой/аятами
  └── предварительные ошибки и диагностические метрики
```

Внешней точкой API должен оставаться Go backend. Он проверяет школу, роль, доступ к заданию и согласие на обработку. Python-сервис получает внутреннее задание и не доверяет данным браузера напрямую.

## Планируемые AI-сущности

- `recitation_assignments` — школа, группа/ученик, сура, диапазон аятов, срок;
- `recitation_attempts` — ученик, задание, статус, объект аудио, версия модели;
- `recitation_detected_errors` — тип, позиция, уверенность, предварительный статус;
- `recitation_reviews` — решение преподавателя, исправление, комментарий;
- `model_versions` — идентификатор модели, настройки декодирования, дата;
- `consents` или ссылка на существующий контур согласий.

Подробная схема и API описаны в `al_qalam_ai_technical_specification.md`.

## Границы безопасности и качества

- Исходное аудио и неподтверждённые выводы недоступны родителю по умолчанию.
- Результат публикуется ученику после решения преподавателя.
- Метрики считаются раздельно по людям и условиям записи.
- Версия модели и настройки распознавания сохраняются с каждой попыткой.
- Срок хранения аудио должен быть ограничен и понятен пользователю.
