# Al-Qalam AI: контекст проекта

Обновлено: **31 октября 2026 года**.

## Что это за продукт

Al-Qalam AI развивается из работающего электронного журнала для медресе и школ Корана. В журнале есть школы, пользователи с ролями, группы, ученики, сотрудники, занятия, домашние задания, посещаемость, оценки, страницы Корана и инфраструктура онлайн-занятий.

Технологический модуль принимает чтение заранее выбранной суры, распознаёт арабскую речь и сопоставляет последовательность слов с текстом. Интерфейс подсвечивает совпавшие слова и места, которые стоит перепроверить. Это помощник преподавателя: текущий прототип не оценивает таджвид, артикуляцию, длительность звуков или религиозную правильность чтения.

## Текущее состояние

| Часть | Состояние |
|---|---|
| Электронный журнал | Реализован на React + Go + PostgreSQL; базовую версию тестирует одна реальная школа |
| Клиентские исследования | По данным автора проекта проведены разговоры/CustDev с двумя медресе; выборка пока мала |
| Страница Корана | Получает список сур, арабский текст, переводы и аудио через внешний API |
| AI-страница `/ai-test` | Работает локально: выбор одной из 114 сур и диапазона до 10 аятов, загрузка аудио и микрофон, быстрая пословная подсветка, прослушивание аятов |
| Поддерживаемый материал AI | Технически все 114 сур через Quran API; локально на реальной записи проверена 112-я сура, остальные требуют предметной проверки |
| Рабочая модель | Локально — предобученная `tarteel-ai/whisper-base-ar-quran` в формате CTranslate2/int8 при наличии файлов; иначе `faster-whisper small`. Оба варианта CPU, beam 5; собственное дообучение не подключено |
| Эксперимент LoRA | Проведён на трёх коротких записях; показал запоминание учебного текста, но независимое улучшение не доказано |
| Хранение AI-результатов | В БД журнала пока отсутствует; веб-записи обрабатываются во временном файле и удаляются |
| Production AI | Не готов: локальный Python HTTP-сервис слушает только `127.0.0.1:8001` |

## Главная задача следующего этапа

Нужно превратить демонстрацию одной суры в проверяемый MVP:

1. Получить точную разметку чтения от преподавателя Корана.
2. Собрать записи разных людей с согласиями и разделить их по людям на разработку и независимую проверку.
3. Измерить ошибки распознавания и качество локализации пропусков, замен и повторов.
4. Проверить динамический каталог на записях 113 «Аль-Фаляк», 114 «Ан-Нас» и 1 «Аль-Фатиха» с разными голосами.
5. Добавить задания, попытки, предварительные ошибки и подтверждение преподавателя в Go backend/PostgreSQL.
6. Провести пилот и сравнить время проверки преподавателем без системы и с системой.

Подробные этапы находятся в [ROADMAP.md](ROADMAP.md).

## Важный ответ про новые суры

Предобученная Whisper уже умеет распознавать арабскую речь в общем виде. Поэтому для технического добавления новой суры не требуется сначала обучать модель или записывать «эталонное чтение». Нужны текст аятов, данные для интерфейса и аудио из Quran API для прослушивания.

Записи всё равно нужны для другого: доказать, что система корректно работает на конкретной суре, голосах учеников, телефонах и реальных ошибках. Для дообучения нужны не просто записи, а точная фактическая расшифровка и разметка преподавателя. Полное объяснение — в [AI_DATA_AND_SURA_EXPANSION.md](AI_DATA_AND_SURA_EXPANSION.md).

## Что запускать

- Для журнала: PostgreSQL → Go backend на `:8000` → Vite на `:5173`.
- Для локальной AI-демонстрации: Python AI на `127.0.0.1:8001` → Vite на `:5173`; backend журнала для `/ai-test` не обязателен.
- Полные команды и требования: [DEVELOPMENT.md](DEVELOPMENT.md).

## Проверки и наблюдения

- `app`: 4/4 теста аудиозахвата прошли; production-сборка Vite прошла.
- `back`: `go test ./...` прошёл; отдельных unit-тестов в пакетах пока нет.
- `ai-service`: тесты анализа, динамического каталога, распознавания, декодирования и tracking проходят. HTTP-интеграцию дополнительно проверили локальным сервисом на диапазонах `112:1–4` и `113:2–5`.
- Предобученная модель Tarteel проверена на пяти локальных записях и подключена как локальный вариант по умолчанию. Повтор живого сценария на 6, 10 секундах и полной пятой записи не пометил непрочитанный хвост как ошибку. Учительской разметки пока нет: улучшение обнаружения реальных ошибок не доказано.
- Для живой подсветки браузер отправляет последние 12 секунд записи примерно раз в 4 секунды; сервер соединяет перекрывающиеся расшифровки в рамках сессии. После остановки финальный запрос с полным аудио отправляется сразу и имеет приоритет над ожидающими промежуточными запросами. Промежуточный результат использует beam 1, финальный — beam 5. Это изменение пока проверено локальными тестами и требует замера задержки и качества на сервере.
- Первый серверный прогон выявил ошибку соединения: когда модель исправляла последние слова предыдущего окна, точное совпадение не находилось и текст дублировался. Теперь совпадающая фраза в соседних окнах позволяет заменить нестабильный хвост. На двух локальных записях «Аль-Ихляс» подсветка выравнивается; качество на новых голосах и серверная задержка пока не подтверждены.
- В ветке `feature/dual-pass-recitation` локально реализован двухпроходный прототип: Tarteel tiny для предварительной подсветки, Tarteel base для подтверждения окон каждые 8 секунд и финала. Tiny лежит в исключённой из Git папке; без неё предварительный проход использует base. На MacBook обе модели работают на CPU. На одной локальной записи tiny ответила за 0,5 секунды, base за 1,5 секунды; это не замер полного пользовательского сценария. Публичный сервер пока не обновлён.
- Исправлен локальный Origin: dev-страница на `127.0.0.1:5173` теперь допускается loopback AI-сервисом; чужие домены по-прежнему отклоняются. Для проверки после изменения Python-кода локальный сервис нужно перезапустить.
- 31 октября 2026 года микрофон возвращён к HTTP-окнам после неудачного испытания WebSocket пользователем. Промежуточные результаты снова отправляются на `/ai-api/listen` и `/ai-api/confirm`, финал — на `/ai-api/listen/final`. WebSocket-эксперимент сохранён в истории Git, но не используется в текущем коде. Отдельная запись автора из «Диктофона» также распознавалась с большим числом искажений обеими моделями; проблема качества ASR остаётся отдельной задачей.
- Для HTTP-подсветки сохранён прежний строгий порог зелёных слов. Если он не достигнут, упорядоченные точные совпадения теперь подсвечиваются жёлтым с подчёркиванием и не считаются подтверждёнными; остальные слова серые. На присланном автором финальном ответе получается 3 жёлтых и 12 серых слов, без зелёных. Слабый финальный ответ больше не стирает ранее подтверждённую предварительную подсветку. Это изменение интерфейса не повышает качество ASR и не доказывает правильность чтения.
