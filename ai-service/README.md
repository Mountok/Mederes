# Первый эксперимент Al-Qalam AI

Локальный CLI-прототип: аудио → арабская расшифровка → сравнение с выбранным диапазоном аятов.
Это готовая предобученная модель, не собственное дообучение и не проверка таджвида.
Текст эталона используется только после распознавания, чтобы не подсказывать модели ответ.

## Запуск

```sh
cd /Users/ruman/Documents/agre/Mederes/ai-service
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest -v
.venv/bin/python baseline.py --model small --output results/current
```

Используются локально скачанные веса; записи не отправляются наружу.
На новом компьютере отдельно скачайте модель перед запуском:

```sh
.venv/bin/python -c 'from faster_whisper import WhisperModel; WhisperModel("small", device="cpu", compute_type="int8", download_root="models")'
```
PyAV декодирует MP3/M4A/WebM/WAV в mono 16 kHz без отдельной установки FFmpeg.
Результаты: `results/current/report.html`, общий JSON и отдельный JSON на файл.
Повторный запуск в ту же папку обновляет результаты; для нового эксперимента задайте `--output results/run2`.
Для сравнения с более крупной моделью:

```sh
.venv/bin/python baseline.py --model small --output results/small
```

Если загрузчик Xet зависает, можно повторить эту команду с переменной
`HF_HUB_DISABLE_XET=1`, чтобы использовать обычную HTTP-загрузку.

### Единый распознаватель v2

`recognition.py` используется и сайтом, и консольным тестом. Одинаковые настройки:
float32 mono 16 kHz, CPU/int8, beam=5, без фильтрации пауз и без подсказки эталонного текста. Веб-сервис выбирает локально конвертированную Tarteel-модель, если её файлы есть в `models/tarteel-faster-whisper-base/`; иначе использует `small`. CLI `baseline.py` требует явного `--model` и подходит для сравнения.
`Recognizer.transcribe(path)` возвращает только распознавание; сравнение с сурой выполняется отдельно.
В результате есть фрагменты с приблизительными временными границами. На сайте их можно прослушивать.
Ограничение длины теперь одинаковое для CLI и сайта: 1–60 секунд.
Старые отчёты используют другой декодер/word_timestamps; не смешивайте их с новым экспериментом.

Экспериментальные настройки (не улучшение по умолчанию):

```sh
.venv/bin/python baseline.py --beam-size 10 --output results/beam10
.venv/bin/python baseline.py --vad --output results/vad
```

Такие же параметры доступны у `server.py`. После изменения Python-кода сервер нужно перезапустить.
На пяти записях режим beam=10 иногда улучшал текст, но на записи №4 выдавал дополнительный
смешанный русско-арабский текст. Поэтому значение по умолчанию оставлено 5, VAD выключен.
Дообучение на этих пяти записях не выполнялось; без ручной расшифровки качество ASR не измерено.

### Предобученная модель Tarteel на текущем MacBook

Локально скачан открытый checkpoint `tarteel-ai/whisper-base-ar-quran` и конвертирован в CTranslate2/int8. Это не собственное дообучение. Для конвертации используется `convert_tarteel.py`; он читает checkpoint из `models/tarteel-hf/hub/` и создаёт `models/tarteel-faster-whisper-base/`. Обе папки исключены из Git. На другой машине можно перенести готовую папку модели отдельно от репозитория; если её нет, предварительно скачайте `small` командой выше. Явный запуск старого варианта: `.venv/bin/python server.py --model small`.

Сравнение пяти локальных записей находится в `RESULTS.md`. Предварительно Tarteel чаще даёт текст ближе к каноническому, но без дословной разметки неизвестно, лучше ли она сохраняет реальные ошибки ученика. Вывод на странице всегда требует проверки преподавателем.

### Локальный двухпроходный прототип

Tarteel tiny используется для быстрых предварительных окон, Tarteel base подтверждает
окна и обрабатывает полную запись после остановки. Tiny сохраняется отдельно от Git:

```sh
HF_HUB_DISABLE_XET=1 .venv-train/bin/python -c 'from huggingface_hub import snapshot_download; snapshot_download(repo_id="tarteel-ai/whisper-tiny-ar-quran", cache_dir="models/tarteel-hf/hub", allow_patterns=["config.json", "preprocessor_config.json", "pytorch_model.bin", "tokenizer_config.json", "vocab.json", "merges.txt", "normalizer.json", "added_tokens.json", "special_tokens_map.json"])'
.venv-train/bin/python -m pip install ctranslate2==4.8.2
HF_HOME="$PWD/models/tarteel-hf/cache" .venv-train/bin/python convert_tarteel.py --size tiny
```

Для `.venv-train` нужны зависимости из `requirements-train.txt`. После конвертации
должны существовать `models/tarteel-faster-whisper-tiny/model.bin` и `tokenizer.json`.
Без tiny сервис работает с одной base-моделью. Предварительная подсветка может измениться;
финальный ответ всегда выдаёт base.

## Интерпретация

`transcript_reference_distance` — расстояние между расшифровкой и ожидаемым аятом,
а не измеренная точность распознавания и не оценка ученика. Нужна дословная ручная расшифровка.
Нормализация убирает огласовки и объединяет варианты алифа: ошибки в этих признаках не обнаруживаются.
Поддерживается необязательная басмала строго в начале. Другие вступления/окончания попадают в расхождения.
Повторы помечаются предварительно: выравнивание повторяющихся слов неоднозначно.
Координаты у вставок указывают ближайшее предшествующее эталонное слово (или первое слово в начале).
Показатель уверенности в правильности чтения пока отсутствует. `avg_logprob` — диагностический сигнал ASR, не вероятность ошибки ученика.
Идентичные декодированные записи отмечаются как дубликаты и не должны считаться независимыми примерами.

Следующий шаг: преподаватель проверяет текст и расхождения; добавляем новые голоса и естественные ошибки,
делим данные по людям на разработку и независимую проверку. Только затем оцениваем precision/recall обнаружения ошибок.
Исходные аудио, веса, окружение и отчёты исключены из Git.

## Тестовая функция на сайте

Первый терминал (окружение и веса small уже установлены на этом компьютере):

```sh
cd /Users/ruman/Documents/agre/Mederes/ai-service
.venv/bin/python server.py
```

Второй терминал:

```sh
cd /Users/ruman/Documents/agre/Mederes/app
npm run dev -- --host 127.0.0.1
```

Откройте http://127.0.0.1:5173/ai-test — либо «AI · тест» на главной или в кабинете.
Если Vite уже работал, перезапустите его после изменения proxy-конфига.
Backend журнала и база для этой страницы не нужны.
Сервис слушает только 127.0.0.1:8001; Vite проксирует `/ai-api` к нему.
Веса загружаются из локального кеша, автоматически ничего не скачивается.

Ограничения: один запрос распознавания одновременно, файл до 20 МБ, аудио 1–60 секунд.
Файл отправляется только по кнопке, хранится временно и удаляется после обработки.
В БД и отчёты веб-записи не сохраняются. Страница поддерживает все 114 сур через Quran API и диапазон до 10 аятов за попытку. Встроенный fallback существует только для 112-й суры; для остальных сур нужен интернет. Техническая поддержка суры не означает проверенную точность на реальных чтениях.
Это локальная демоверсия: `vite preview` и статическая production-сборка не предоставляют этот proxy.
Для публичного развёртывания отдельно нужны авторизация, квоты, HTTPS и серверный reverse proxy.
Сервис остаётся привязанным к `127.0.0.1`; при работе через домен укажите точный origin
параметром `--allowed-origin`, например `--allowed-origin https://al-qalam.ru`.
Не используйте `*`: это не безопасная настройка для загрузки аудио.
Не открывайте Python dev-сервис или Vite в интернет.

## Микрофон и подсветка (эксперимент)

На `/ai-test` кнопка «Начать чтение» запрашивает микрофон после проверки доступности API.
Требуются localhost/HTTPS и браузер с AudioWorklet. Локально используется Tarteel/CTranslate2 при наличии файлов, иначе `small`; экспериментальный LoRA-адаптер автоматически не подключён.

AudioWorklet собирает моно PCM; браузер формирует WAV-окна из последних 12 секунд
примерно каждые четыре секунды. Предварительные запросы используют tiny с beam 1, подтверждающие каждые восемь секунд — base с beam 5, финальный — base с beam 5. Сервер соединяет перекрывающиеся расшифровки каждого прохода отдельно в пределах сессии;
устаревшие ожидающие снимки заменяются последним. Финальный запрос отправляется сразу после
остановки, имеет приоритет над ожидающими промежуточными запросами и заново проверяет полную
запись. Уже начавшийся вызов модели нельзя прервать: финал ждёт его завершения.
Это оконная имитация потокового распознавания, а не настоящая потоковая модель.
Сессия ограничена 55 секундами; при остановке отправляется последний снимок, микрофон освобождается.
При уходе со страницы останавливаются дорожки, аудиоконтекст, таймер и запрос.

`POST /ai-api/listen?surah=112&ayah_from=1&ayah_to=4` возвращает предварительную подсветку;
`POST /ai-api/confirm` — уточнение основной моделью во время чтения;
`POST /ai-api/listen/final` с теми же параметрами — финальную для полученного фрагмента.
`tracking.py` выравнивает распознанный текст с префиксом суры: непрочитанный хвост остаётся нейтральным.
Два последних слова промежуточного результата отмечаются как уточняемые.
Повтор, замена или внутренний пропуск — повод проверить, не заключение об ошибке.
Подсветка может пересматриваться после следующего распознавания. Повторное чтение с середины
и оценка таджвида не поддерживаются. Отсутствие расхождений не подтверждает произношение.

Проверки:

```sh
.venv/bin/python -m unittest -v
.venv/bin/python verify_live.py
cd ../app
node --test tests/recitation.test.mjs
npm run build
```

`verify_live.py` отправляет локальному сервису первые 6, 10 секунд и полную пятую запись,
проверяет, что будущие слова не помечены ошибками, и сохраняет отчёт в `results/live-replay/`.
Это проверка API на записи, не проверка аппаратного микрофона.
