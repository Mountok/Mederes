# Контекст для работы с Al-Qalam AI

Этот файл относится ко всему репозиторию. Перед изменениями прочитайте:

1. `docs/START_HERE.md` — актуальное состояние проекта и ближайшая цель.
2. `docs/FACTS_AND_HYPOTHESES.md` — что подтверждено, а что остаётся гипотезой.
3. Профильный документ: `docs/DEVELOPMENT.md`, `docs/ARCHITECTURE.md` или `docs/AI_DATA_AND_SURA_EXPANSION.md`.
4. `git status --short` — в рабочей папке могут находиться незакоммиченные изменения пользователя.

## Кратко о проекте

Al-Qalam AI — электронный журнал для медресе и школ Корана с экспериментальным модулем анализа чтения. Журнал и AI-прототип уже существуют. По проверке автора отдельная практика работает и на сервере через HTTPS; новый контур домашних заданий пока проверен локально и не развёрнут публично. AI технически принимает выбранный диапазон любой из 114 сур через Quran API. Ответы на задания сохраняют предварительный анализ в PostgreSQL и аудио на локальном диске; отдельная практика `/ai-test` без задания не сохраняет результаты. Реальными локальными записями проверялась прежде всего сура 112 «Аль-Ихляс».

Локальный AI сайта использует предобученную `tarteel-ai/whisper-base-ar-quran`, конвертированную в CTranslate2/int8, если её файлы есть в `ai-service/models/`. Без них сервис использует `faster-whisper small`. Это предварительный выбор по пяти неразмеченным записям, а не доказательство качества. Экспериментальный LoRA-адаптер к сайту не подключён. Вывод алгоритма означает совпадение распознанных слов с текстом, а не проверку произношения, огласовок или таджвида.

## Обязательные границы

- Не называйте подсветку «оценкой правильности чтения» или «проверкой таджвида».
- Не подменяйте распознавание эталонным текстом и не передавайте полный ожидаемый аят как подсказку ASR при измерении качества.
- Не подключайте LoRA-адаптер к рабочей странице без отдельной независимой проверки на людях, которых не было в обучении.
- Не считайте расстояние до текста суры точностью ASR или числом ошибок ученика без дословной учительской расшифровки.
- Не обучайте модель на новых записях только потому, что известно, какую суру человек собирался читать. Нужна фактическая расшифровка и статус разметки.
- Не коммитьте аудиозаписи, веса, виртуальные окружения, результаты экспериментов, секреты и `.env`.
- Сохраняйте существующие незакоммиченные изменения пользователя и не выполняйте destructive Git-команды.

## Правила реализации

- Сохраняйте разделение каталога и распознавания: выбранный диапазон загружается через `ai-service/quran_catalog.py`, а ожидаемый текст не передаётся в ASR.
- Текст выбранной суры должен передаваться в слой сравнения после получения сырой расшифровки.
- Любой результат для ученика имеет предварительный статус до подтверждения преподавателем.
- Для production AI должен находиться за Go API/reverse proxy, авторизацией, квотами и HTTPS. `ai-service/server.py` — только loopback dev-сервис.
- При изменении поведения обновите соответствующий документ в `docs/` и поле «Обновлено» в `docs/START_HERE.md`.

## Проверки

Из корня репозитория:

```bash
cd app && node --test tests/recitation.test.mjs && npm run build
cd ../back && GOCACHE=/tmp/al-qalam-go-cache go test ./...
cd ../ai-service && .venv/bin/python -m unittest -v
```

HTTP-тесты AI создают локальный TCP-сервер. В изолированной среде они могут завершиться `PermissionError: Operation not permitted`; тогда отдельно проверьте тесты анализа, распознавания и tracking, а HTTP-набор запустите на обычной локальной машине.
